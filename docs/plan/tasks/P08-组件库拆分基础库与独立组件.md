# P08. 组件库拆分：基础库 + 独立复杂组件库

- 状态：`[ ]`
- 目标：将 antd_flutter_plus 全量包拆分为「基础组件库（antd-base 类）+ 独立复杂组件库（antd-picker 类）」，支持两种接入方式：**全量接入**（伞包）与**单独接入某个复杂组件**；拆分必须有足够理由，不为拆而拆
- 前置依赖：建议在 P03/P05/P07（antd_theme 增强）之后执行，避免拆分期间主题层接口变动；纯规划阶段可提前

## 拆分原则（核心）

### 独立拆分准入标准（同时满足越多越应拆，硬性至少 3 条）
1. **功能复杂度**：组件实现复杂（自绘引擎/复杂手势/状态机），代码量显著高于均值（如 Table、Calendar、Picker 系）
2. **依赖隔离度**：自带三方依赖（qr_flutter、cached_network_image 等）或自身子模块多，全量接入时给不需要的用户带来额外依赖负担
3. **独立使用场景**：存在大量「只用这一个组件」的真实场景（如只想用 Picker/Table/QRCode 的 App）
4. **独立演进需求**：版本节奏/ Breaking change 与主库不同步（如 Picker 需要频繁迭代但主库求稳）
5. **体积影响**：含资源文件（字体、图片、图标）或显著增加包体积

### 不拆标准（命中即留在基础库）
- 被其他组件广泛依赖的基础能力（Space/Flex/Theme/ConfigProvider/Typography 等）
- 简单展示/布局组件（拆出去没有使用价值增益）
- 与其他组件强耦合、拆出需连带一堆依赖的

## 目标结构规划

### 基础库命名
- 已定名：**`antd_flutter_ui`**（基础组件库，内容以 UI 组件为主，语义直白；skill 命名对应 `antd-ui-dev`）

### 双端源码基线（重要约定）
- 现状：绝大多数组件基于 **antd v6（桌面端）** 源码实现，少数（标注 📱 的）基于 **antd-mobile v5（移动端）** 源码
- 本次拆分重构中做**双端兼容**评估：每个组件判断是否需要桌面版/移动版两套实现，**不是所有组件都需要**，判断标准：
  1. 交互形态双端差异大（如 Picker 桌面下拉 vs 移动滚轮、Table 桌面复杂操作 vs 移动简化）→ 倾向双实现或响应式自适应
  2. 双端视觉/交互基本一致（Button/Card/Tag 等）→ 单实现 + 响应式样式即可
  3. 仅单端有意义的组件 → 单实现
- 实现路径优先级：优先**单实现 + 响应式自适应**（经 AntResponsive 断点/设备类型切换形态），差异过大无法自适应的才做双实现；评估结论进拆分清单表
- 源码对齐基线：桌面组件以 antd v6 源码为准，移动组件以 antd-mobile v5 源码为准

### 每库配套 Skill
- 拆分完成后，为每个库编写一个 skill（经 skill-factory 生成，命名如 `antd-ui-dev` / `antd-picker-dev`）：内容包含该库的组件清单、对应 antd/antd-mobile 源码版本与目录映射、双端形态决策表、源码对比修改更新流程（改组件前先与上游源码 diff 对齐再动手），方便后续直接使用 skill 做源码级同步更新

```
antd_flutter_plus        ← 伞包（全量接入入口，依赖并 re-export 下方全部）
packages/
├── antd_color           （已独立）

│   ├── 通用展示：Avatar/Badge/Tag/Card/Empty/Statistic/Image/ImageViewer/Popover/Tooltip/Segmented/NoticeBar/QRCode?*
```

## 步骤
1. **依赖审计**：扫描 111 个组件的 import 图，输出「组件 → 内部依赖 → 三方依赖」矩阵，量化每个组件的复杂度与耦合度，作为准入标准打分依据
2. **拆分清单裁决**：依据审计结果 + 准入标准给出最终拆分清单（含每个组件的去向和理由表）+ **双端兼容决策表**（单实现自适应 / 双实现 / 单端，附 antd v6 或 antd-mobile v5 源码依据），**提交用户确认后**才动代码
3. **基础库抽离**：建立 `antd_flutter_ui`（已定名），迁移基础组件（无接口变更，纯搬家 + export 路径调整），主包保留 re-export 保证兼容
4. **双端兼容落地**：按决策表逐组件实施（自适应形态经 AntResponsive 切换；双实现组件在单包内提供桌面/移动两个变体 + 自动选择）
5. **独立组件抽离**：按清单逐个拆出（每拆一个：建包 → 迁移代码+测试+example → 主包 re-export → CI 更新 → 验证），一次一个组件族
6. **伞包整合**：`antd_flutter_plus` 改造为纯伞包（或保留少量 glue），全量接入 = 依赖伞包；单独接入 = 直接依赖 `antd_picker` 等
7. **CI/发布适配**：CI 矩阵覆盖全部子包；发布策略：基础库与伞包跟随主版本，独立组件库独立版本号（修订同步主库 token/theme 大版本约束）
8. **每库 Skill 编写**：经 skill-factory 为每个库生成配套 skill（组件清单/源码基线映射/双端决策表/源码对比更新流程），录入工作区技能体系
9. **文档适配**：README 接入方式说明（全量/按需）、组件表标注所属包与双端形态

## 编码标准（全程适用）
- 遵循工作区规则（AGENTS.md / dev-conventions）：**DRY 原则**（重复字符串/数字/判断逻辑提取为常量或公共方法，常量命名体现业务语义）；**三方 SDK 中间件隔离**（SDK 方法经 wrapper/adapter 隔离，接口命名体现业务语义）
- 双实现组件的桌面/移动变体共享的样式/逻辑必须提取公共层，禁止复制粘贴两份
