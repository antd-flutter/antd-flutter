# P05. 响应式布局信息通知（AntResponsive）+ 平台信息并入主题

- 状态：`[ ]`
- 目标：提供 Flutter 风格命名的布局信息工具 `AntResponsive`（原方案名 AntLayoutStatus，按 Flutter 命名习惯调整），支持**多种粒度的通知/判断模式**；主工程平台判断迁入 antd_theme，布局变化时同时通知平台信息；调研折叠屏（尤其 OHOS）信息返回，能全局则全局支持，不能则做好 OHOS 兼容适配
- 前置依赖：无

## 命名与 API 规划（Flutter 惯例对齐）
- Widget/Scope：`AntResponsive`（类似 `Theme`/`MediaQuery` 的外侧包裹，builder 形式 `AntResponsive(builder: (ctx, layout) => ...)`）
- 数据模型：`AntLayoutData`（不可变快照，字段见下）
- 读取入口：`AntResponsive.of(context)`（InheritedWidget 依赖，局部 rebuild）、`AntResponsive.maybeOf(context)`
- 细粒度订阅（避免无关字段变化触发 rebuild）：`AntResponsive.breakpointOf(ctx)` / `deviceTypeOf(ctx)` / `foldStateOf(ctx)` / `platformOf(ctx)` 等便捷方法，内部按 aspect 做依赖拆分（参考 `MediaQuery` 的 aspect 机制）
- 订阅式（非 Widget 场景）：`AntResponsiveScope` 暴露 `ValueListenable<AntLayoutData>` 或 addListener

## AntLayoutData 字段（多模式通知判断）
1. **宽度/断点模式**：`width`、`AntBreakpoint? breakpoint`（纯宽度响应式判断）
2. **设备类型模式**：`AntDeviceType deviceType`（phone/tablet/desktop/web，按宽度+平台综合判定，阈值可配）
3. **方向模式**：`orientation`（portrait/landscape）
4. **折叠屏模式**：`AntFoldState foldState`（unknown/flat/halfOpened/folded，来源见步骤 3）
5. **平台模式**：`targetPlatform` / `isOhos` / `isDesktop` 等能力便捷字段
- 通知去重：`AntLayoutData` 实现 `==`，值不变不发通知；细粒度方法只比较对应 aspect

## 现状盘点
- `packages/antd_theme/lib/src/ant_breakpoint.dart`：已有 `AntBreakpoint` 枚举（xs~xxxl）+ `fromWidth`/`of(context)` 静态解析，**无变化通知机制**
- 主工程 `lib/src/platform/ant_platform.dart`：`AntPlatform` 静态类（isDesktop/isMobile/isOhos/能力判断），在主工程，antd_theme 包无法引用（依赖方向：antd_theme 是独立包）

## 步骤
0. **前置清理（总规则 R24）**：替换残留的 `flutter/material.dart` import 为 `package:material_ui/material_ui.dart`（当前已知：packages/antd_color/example、packages/antd_theme/example、packages/antd_tokens/example 的 example 与测试文件）；完成后全文检索确认无残留
1. **布局信息通知工具**（antd_theme 内）：
   - 按「命名与 API 规划」实现 `AntResponsive` / `AntLayoutData` / 细粒度 aspect 订阅
   - 监听入口：类似 `AntScreenUtilInit` 的初始化 Widget，或挂在 `AntTheme` 内，`MediaQuery` 变化时仅值真正变化时通知
   - 使用方式：`AntResponsive.of(context)`（局部 rebuild）、细粒度 `breakpointOf` 等、`addListener` 订阅（非 Widget 场景）
   - 通知前做相等性判断（值不变不通知；细粒度方法只比 aspect）
2. **平台信息并入主题**：
   - 平台判断逻辑从主工程 `AntPlatform` 迁移/下沉到 antd_theme（主工程改为 re-export 或引用，保持 `AntPlatform.isOhos` API 兼容，防止已有使用方破坏）
   - 布局信息中携带平台信息，布局变化时一并通知，方便用户适配
3. **折叠屏信息调研与适配**：
   - 调研 OHOS 折叠屏适配 API（display 特征/折叠态：展开、半折、折叠；参考 OHOS 官方 display 文档与鸿蒙适配实践），经 `AntOhosChannel`（已有抽象接口）透出
   - 调研 Flutter 侧 `Display` API / `MediaQuery` 对折叠屏的表达能力（displayFeatures）
   - 能全局获取：并入 `AntLayoutData.foldState`（unknown/flat/halfOpened/folded 等），跨平台统一
   - 不能全局：仅 OHOS 经 channel 返回，其他平台给默认值，不阻塞
4. example 演示页：布局信息实时展示（断点/设备类型/方向/平台/折叠态），验证局部刷新与细粒度订阅（仅依赖 aspect rebuild）
5. 单元测试：断点解析、通知去重、平台信息携带；OHOS channel 折叠态 mock 测试
6. `flutter analyze` + `flutter test` 通过

## 验收标准
- [ ] `AntResponsive` 提供宽度/设备类型/方向/折叠屏/平台多种判断与通知模式
- [ ] 细粒度订阅生效：无关字段变化不触发 rebuild
- [ ] 用户可通过局部刷新（不整页 setState）感知布局变化
- [ ] 平台判断统一入口在 antd_theme，主工程 API 向后兼容
- [ ] 折叠屏：OHOS 有信息返回则全局可用；无则其他平台默认值 + OHOS 兼容路径就绪
- [ ] 测试通过

## 备注
- 规则遵循：通知去重（值相等不发通知）；OHOS 平台判断严禁 `Platform.isOhos`
- 折叠屏 API 以调研结论为准，本文件步骤 3 保留两种落地路径
